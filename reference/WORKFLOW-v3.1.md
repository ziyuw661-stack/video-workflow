# 视频生成工作流 v3.1（个人独立运行）

- 版本：v3.1（2026-11-26）
- 定位：**一套固定流程，每人在自己电脑上、与自己的 AI 一起按流程生成视频**。共享的是规范与程序，不共享个人密钥、声音、素材及运营数据；无需建设集中平台或采购服务器。素材库每人自建（搭建步骤见 §二）。首次接入先执行 §零。
- 特点：成片交付、免费优先、模块化、双平台、附验收清单。
- 适用：每人在自己电脑上运行，适用于 Windows 与 Mac，工具按需选。
- 成品：横屏 16:9 长视频（YouTube，5 分钟以上，时长不固定）＋竖屏 9:16 短视频（TikTok），同一脚本出两种规格。

## 一、三层结构

| 层 | 内容 | 所有人一样吗 |
|---|---|---|
| L1 共享骨架 | 9 步流程 + 查证清单 + 验收清单 + 发布规范。解决"做什么、按什么顺序、怎么算合格"，与风格无关 | 一样 |
| L2 可换模块 | 配音、画面、脚本三类模块，每个 2–3 个已验证选项 + 切换成本 | 按风格选 |
| L3 成员配置 | 每人一张配置卡（存在本地，不进仓库）：账号定位、语言、声线、画面风格、发布节奏 | 每人不同 |

## 零、新成员接入：首次接入路径（一次就够）

首次接入按以下顺序执行，通过一项再做下一项：

1. **环境检查**：确认本机终端、文件及网络权限；检查 Python、FFmpeg、Git 是否可用。
2. **安装**：按 §五与 §十安装固定版本工具（Python 依赖进独立虚拟环境并锁定版本）；工具安装失败即停用对应功能，记录原因，不虚构已安装。
3. **填写配置**：按 §四填一张配置卡（方向、市场与语言、声线、画面风格、平台、成品规格、节奏），存在本地。
4. **授权验证**：按 §十第 8 步做一次 Google 授权（每人自己的账号），并做一次私享测试上传，确认频道与权限无误。
5. **声线与风格确认**：声线试听一次，画面风格做一条 15–30 秒小样；确认后写入配置表锁定，之后每条直接产出成片，不再做样片。
6. **完整成片验收**：用真实选题完整跑通一条，逐段最后一帧检查，通过 §七验收清单。
7. **启用定时任务**：验收通过后才启用本机定时任务（Windows 任务计划程序 / macOS launchd / Linux cron）；电脑须保持可执行状态。

配置卡未填项，默认采用 §三标注为 A 的示例配置，后续可调整。成员只确认目标、偏好和必要权限，不负责搜关键词或找对标账号；初始采集策略由 AI 提出，成员确认后在已确认方向内持续更新，明显改变定位才重新确认。

## 二、L1 共享骨架：9 步

9 步中成员参与第 1、7、8、9 步（选题、验收、发布包确认、发布），其余步骤由成员与自己的 AI 在本机执行。

| 步 | 做什么 | 工具（免费优先） | 输入 → 输出 | 验收 |
|---|---|---|---|---|
| 1 选题 | 选 1 条，来源三选一（写进成员配置表） | A 素材库：从自己的素材库中选取（自建步骤见下；按成员配置每日自动抓取更新）；B 无库现找：按下方 B 流程查找；C 手动指定：直接提供一个选题或链接；期权另有专属路径（国内文稿 → 海外适配，见下） | 爆款链接 + 数据 → 选题单 | 记录来源与数据，不凭感觉选择 |
| 2 查证 | 原片 / 原文核对数字、说法、口径 | 查证表 `core/templates/fact-check.md` | 脚本草稿 → 查证记录 | 每个数字应有出处；来源、数字口径与上屏镜头一一对应；无法核实则删除该数字，不得编造；作者自报内容应注明「作者自报」 |
| 3 改写 | 两条路：改稿，或热点直出（见 §三） | 改写框架（见 §三）+ 提示词 `prompts/`；目标用户（语言、市场、受众）按成员配置表填写 | 原片 / 热点 → 脚本 + 分镜表 | 观点不变，表达、例子、比喻全部重写；钩子应在 0–3 秒内让观众理解 |
| 4 配音 | 按成员配置表选定声线（男 / 女、音色），全片统一，不再更换 | 系统端 TTS 合成（声线选项见 §三；MAI_03 为示例配置，仅供参考）；多个声线候选时同稿等响度比较后再定 | 脚本 → 音频 + 时序表 | 配音、字幕、画面逐句对应；每元素配真实配音片段，最短 1.2 秒 |
| 5 画面 | 按成员配置表中的画面风格执行 | 白板手写 / 对话出镜 / PPT 动画 / 实拍剪辑，见 §三（白板为示例配置，仅供参考；白板规则见 `rules.md`，仅适用于选择白板风格者）。说明：白板目前无统一渲染入口，每期为一个定制 build 脚本（见 §三画面说明） | 分镜表 → 画面 | 图形应自带细节与标签，无法辨认的应重画；版式每页更换骨架 |
| 6 合成 | 字幕烧录、音效、转场 | FFmpeg + numpy 混音（`core/scripts/mix_sfx.py`）；保留可编辑时间轴（OpenTimelineIO），而非仅保留成片 | 画面 + 音频 → 整片 | 音效仅在绘制图形或书写关键数字时播放，音量低于配音；不得使用 ffmpeg amix 多路混音（会导致长时间卡顿） |
| 7 验收 | 成员在待审核队列逐段最后一帧检查 | 验收清单 `core/templates/acceptance-checklist.md` | 整片 → 验收结果 | 最后一帧逐页查：无重合、无溢出、无遮挡、无乱码；结尾有引导关注与免责声明；上传前校验最终 MP4 和字幕与复核记录一致 |
| 8 发布包 | 标题、简介、标签、封面 | 发布包模板 `core/templates/publish-package.md` | 整片 → 发布包文档 | 数字应先查证再写入发布包；封面按实际开头画面制作 |
| 9 发布复盘 | 私享审核 → 定时公开 → 看数据 | YouTube 官方 API（私享 + publishAt，各成员自己的账号）、TikTok 手机 App 手动 | 发布包 → 上线链接 + 复盘记录 | 先设为私享，确认后再公开；复盘以留存率与完播率为主要指标，而非仅看播放量 |

### 共享素材库无合适选题时，查找爆款（B 流程）

1. 在 YouTube 搜索领域关键词，按播放量排序，仅查看最近 30 天的内容。
2. 打开 3–5 个同领域头部频道，查看其近 30 天播放量最高的 3 条。
3. 同频道内比较：同一频道、相近时长、相近发布天数的视频比较播放量，选取超出该频道平均值的条目（不与全网比较）。
4. 记录：标题、链接、播放量、发布日期、时长，写入选题单。
5. 或直接向系统提供一个选题或链接，跳过前面四步。

### 素材库结构（表结构与分类）

一张表 9 列：日期、方向、平台、关键词、标题、频道、播放量、发布时间、链接。示例方向：期权、娱乐、平台热门（每个方向 4 个英文关键词，写在爬虫脚本里）；每位成员的方向按自己的配置设定（3–5 个），见成员配置表。

### 自建素材库

每位成员自建一个素材库，各自维护：

1. 按上方表结构建表（9 列）。
2. 在爬虫脚本 `CATEGORIES` 中填入自己的方向与关键词（3–5 个方向，每个方向 4 个英文关键词）。
3. 按成员配置每日运行爬虫，结果写入该成员的素材库。
4. 国内平台与 TikTok 按下方手动补充。

期权方向可共用一个启动包：已验证的国内爆款选题脱敏后放入 git，供新成员作为初始数据。

### 抓取方式：爬虫脚本（YouTube 自动）

仓库内置 `core/scripts/trend_crawler.py`，仅抓取公开元数据，不下载视频、不搬运：

1. 安装（首次使用时一次完成）：`pip install --user yt-dlp`（脚本用 `python -m yt_dlp` 调用，安装一次即可）。
2. 运行：按成员配置定时运行（具体时间由成员设定），默认每个关键词取前 5 条；每位成员的方向与关键词写在各自配置的 `CATEGORIES` 中，抓取结果写入该成员的素材库。
3. 输出：当日 `output/trends-YYYY-MM-DD.csv` 与累积 `output/all-trends.csv`（按链接去重）。
4. 写入素材表：仅添加新链接，英文标题翻译为中文，新日期置于上方、旧日期依次下移，同日按播放量倒序排列。写表方式：禁止使用插入行（spreadsheets.batchUpdate / insertDimension），该操作每次运行均需人工批准，定时任务将被阻塞等待批准。应使用单元格更新（spreadsheets.values.update）：先读取整张表，将新行置于最前、旧行原样下移，再以 values.update 将该区域按新顺序一次性写回；区域不足时以 values.update 写入更大区域，不插入行；不使用 values.append（新行将落至表尾）。
5. 发布时间说明：yt-dlp 的 flat 搜索不返回发布时间，需通过视频页核查补充，无法核实填「未知」，不得编造。收录优先选择近 90 天内的内容；如无合适内容，放宽至 6 个月；仍无合适内容，可选用老视频并在标题后注明「（经典参考）」。

### 国内平台与 TikTok：手动补充（不直接爬取）

上述平台存在登录限制，不建议直接爬取单个视频。每日查看官方公开趋势页：TikTok Creative Center、抖音热榜、小红书创作中心、视频号助手，每个平台每日至少补充 3 条，同样写入素材表。视频号无公开热榜时，记录助手入口并注明，不得虚构视频。

### 每日例行

定时执行：每日执行一次（具体时间由成员设定），执行后将新增结果写入素材表。每周清理一次：删除过期条目，标注已使用条目。

素材库每人自建、各自维护，每位成员从自己的库中选取，选题不重复。期权方向可共用一个启动包：已验证的国内爆款选题脱敏后放入 git，供新成员作为初始数据。

### 期权专属：国内文稿 → 海外适配

1. 打开国内文稿文件夹，按播放量选取爆款文稿。
2. 按海外用户习惯重写：知识、数字、策略不变；例子、比喻、平台、语气、监管提示按海外市场调整。
3. 发布至 YouTube 前验证：在 YouTube 搜索同主题，如存在同主题爆款，说明该选题可迁移，直接制作；否则先制作一条进行测试。

### 没有样片这一步

自动化的含义为直接产出成片：风格与声线在成员首次接入选定时各制作一条测试，确认后写入成员配置表锁定；此后每条直接产出成片，不再制作样片。早上验收的对象为成片，而非样片。

## 三、L2 可换模块

成员接入时在配置表中选定自己的选项，选定后不再更换，生成时按配置表执行；标注为 A 的选项为示例配置，仅供参考。首次选择声线、画面风格时，分别制作一条测试，确认后写入配置表锁定；此后每条直接产出成片，不再设置样片环节。

### 脚本框架

| 选项 | 适用 | 说明 |
|---|---|---|
| A 对标改写 | 短视频科普 | 钩子 0–3 秒 → 承诺 → 生活比喻讲概念 → 拆 3 步层层递进 → 一个反例误区 → 数字验证 → 总结口诀 → 免责声明 + 关注 |
| B 双人对话 | 对谈、访谈类 | 两人一问一答，围绕真实数值展开讨论；首次制作一条测试，验证停顿与入镜效果 |
| C 课程结构 | 课程长片 | NotebookLM 生成 PPT → 转动画 |
| D 热点直出 | 当天热点、突发新闻 | 无需改稿：向 AI 提供一个热点链接或关键词及目标用户（语言、市场、受众），直接生成脚本 |

### 配音

| 选项 | 适用 | 说明 |
|---|---|---|
| A 工具选声 | 全片统一 | 男声 MAI_03（白板版）或女声 Aria；每期选定后全片统一，不再更换 |
| B 录音克隆 | 真人感 | 录制 30 秒自己的声音，通过 CosyVoice 3 / Fish Speech / XTTS v2 开源克隆，更换语言后仍使用同一音色；团队长期方向，首次制作 60 秒测试进行比对 |
| C 双人对谈声线 | 对话类 | 两人声线区分开，等响度比较后再定 |

配音在本机执行。用所选 TTS 工具按段合成音频，音色全片统一（工具选项见 §三）。Edge TTS 需可访问 Bing 服务，否则选用本地 TTS。选型：应先确认本机是否配备 NVIDIA 独显（执行 `nvidia-smi`）。配备独显：选用 Qwen3-TTS 1.7B 或 VoxCPM2；无独显：选用 XTTS v2（CPU 可运行，6 秒克隆，17 种语言）。如系统运行在 Mac（Apple Silicon）：选用 Chatterbox（mlx-audio，Turbo 约 4 倍实时）或 Qwen3-TTS 社区 MLX 版；VoxCPM2 可运行但速度较慢。通用选项：XTTS v2 与 VoxCPM2；零成本备选方案为 Edge TTS。克隆录音各工具仅需 3–30 秒。许可说明：Fish Speech S2-Pro 权重与 XTTS v2 权重并非完全免费商用，商用前应先确认；CosyVoice 3、Qwen3-TTS、VoxCPM2、Chatterbox 为 Apache 2.0 / MIT，可商用。

### 画面

| 选项 | 适用 | 说明 | 切换成本 |
|---|---|---|---|
| A 白板手写 | 科普短视频 | 纯白板 + Caveat 手写体 + 正常肤色右手；规则见 `rules.md`。说明：白板已出 8 版成片，但无统一渲染入口，每期为一个定制 build 脚本，通用渲染器待建；新成员照做需以 v8 脚本为起点改写，不可直接运行 | 已验证 8 版，示例见 `examples/` |
| B 对话出镜 / 动画 | 对谈、访谈类 | CapCut / Codex 剪辑，动态图解。说明：仅有说明文档，无脚本 | 需拍摄或动画制作时间 |
| C PPT 动画 | 课程长片 | NotebookLM 生成 PPT → 动画。说明：PPT 生成管线（`build_ppt.py`）需安装 `python-pptx`（`pip install python-pptx`） | 需 PPT 素材 |
| D 短视频批量 | 短视频、批量出片 | MoneyPrinterTurbo（开源 MIT，仍在维护，v1.3.11）：话题 → 脚本 → 素材 → 配音 → 字幕 → 渲染，全流程覆盖；Windows 提供一键安装包，Mac 通过 uv 或 Docker 运行，无需独显。说明：仅有说明文档，无脚本，未验证，选用前须先做一条测试 | 免费，在本机运行 |

自定义：如以上均不适用，可自行描述一种风格，由 AI 按描述制作，首次制作一条测试确认后写入配置表锁定。

## 六、常见问题（均为实测经验）

1. **音效混音不得使用 ffmpeg amix 多路**：24 路混音会导致长时间卡顿，应使用 numpy 混音（`core/scripts/mix_sfx.py`）。
2. **图标位置不得估算**：一律按文字实测宽度（PIL textlength）计算位置，否则会压字。
3. **不得绘制空形状**：轮子应有辐条、轮毂与转动箭头，房子应有烟囱、窗户与门，钟应有刻度与指针，日历应有月份头。
4. **自查应查看每段最后一帧**，而非中间帧；修改一处后，全片复查同类问题。
5. **不进行现场渲染**：整片渲染约需 3–4 分钟，演示与验收应使用预渲染成品。
6. **数字前后不一致的不予采用**：原片字幕中两个版本的数字（如 $29 与 $210）均不采用。
7. **涉及具体公司或人物时，必须使用真实画面**，不得以通用素材代替；同一素材全片仅使用一次。
8. **发布前先设为私享，确认后再公开**；TikTok 仅通过手机 App 手动发布，不使用第三方代发。
9. **音效混音脚本 `core/scripts/mix_sfx.py` 为 v4 专用**：输入与总时长写死，不可直接复用于其他期，复用前需改写为通用脚本。
10. **写表禁止插入行**：见 §二抓取方式第 4 步，插入行每次运行均需人工批准，会阻塞定时任务。
11. **成片硬门槛**（任一条失败不得发布）：完整解码、目标画幅、音视频时长差不超过 0.15 秒、字幕时间单调且不越界、无意外黑帧或静音、文本不溢出 / 不遮挡 / 不乱码、来源与素材许可齐全。

## 八、定时发布方案（定时生成 → 早上验收 → 通过即发 → 数据复盘）

执行时间（生成时间、验收时间、每日条数）待定，以下为暂定方案。

待审核队列：本地文件夹（成片＋发布包）＋素材表待审核表（链接与状态），为成员审片入口。定时任务在本机运行，每账号独立配置采集、生成、审核、发布时刻及 IANA 时区；定时任务只运行已通过验收的固定版本，生成与发布分离。

### 每天的节奏

| 时间 | 谁做 | 做什么 |
|---|---|---|
| 07:00（暂定） | 定时任务 | 检查素材收件箱有无新课素材，有则优先制作该课；没有则按第 1 步的选题来源选一条，按成员配置生成一条，放进待审核队列 |
| 08:00（暂定） | 成员 | 打开待审核队列逐条审核，通过或退回修改 |
| 通过后 | 系统 | 按下表发布；YouTube 与公众号全自动，其余平台由浏览器预填，待执行人点击发布 |
| 之后 | 成员 | 仅需查看数据并抽查 |

### 发布模式

| 模式 | 执行条件 |
|---|---|
| A 人工发布 | 自动成片与发布包，成员审核后在创作中心上传、设置时间 |
| B 审核后自动发布（优先） | 审核锁定成片版本，获准官方接口上传及定时，状态回填 |
| C 无人值守 | 仅平台允许、低风险、连续验收合格且成员明确启用；财经与高风险热点必须人工审核 |

### 两档

- **A 档，验收制（现在）**：每条均需通过 08:00 验收，确认后发布。
- **B 档，免审直发（风格定型后）**：选题、画面、声线定型后，生成完成即按设定时间发布，执行人仅需查看数据并抽查。白板方案已满足 B 档条件，是否免审由各系列负责人逐个决定，默认不开启。

### 发布矩阵

| 平台 | 最优方式 | 前置条件 |
|---|---|---|
| YouTube | 官方 Data API，私享＋publishAt 定时公开，全自动 | 各成员为自己的账号做一次 Google 授权 |
| 公众号 | 官方草稿 / 发布 API，全自动 | appid＋appsecret |
| 抖音 | 平台原生定时发布＋浏览器预填，由执行人点击发布 | 需先发布足够数量解锁定时发布功能；官方 API 需公司主体，个人账号无法开通 |
| 视频号 | 平台原生定时发布＋浏览器预填，由执行人点击发布 | 实名＋近 30 天 3 条原创 |
| TikTok | 手机 App 手动发布，或官方 Direct Post API 立即发布 | API 需应用审核，且无定时参数 |
| 小红书 | 浏览器预填后由执行人点击发布，或手机 App 手动发布 | 需保持登录状态；存在风控，发布量不宜过大，发布间隔应拉开 |

### 浏览器预填流程（适用于无接口的平台）

1. 打开对应平台创作中心上传页（抖音创作中心、视频号创作中心、小红书创作中心）。
2. 上传成片，按发布包填写标题、简介、标签、封面。
3. 设置定时发布时间（使用平台原生定时功能）。
4. 停在发布按钮前，由执行人手动点击发布。不采用无人值守自动点击发布：新账号存在被判定为机器操作的风险（抖音账号健康分会对批量发布扣分）。账号正常发布 1–2 周后，再考虑全自动点击发布。

## 十、实际生产流程（已跑通的制作方法，按此执行）

以下流程为 2026-11-25 白板版 v8 实际执行的步骤，照此执行可复现同类成片。参考实现在 `examples/landlord-method-v8/build_v8.py` 与 `core/scripts/`，分镜稿格式见 `examples/landlord-method-v8/script_v8.json`。

### 输入

每期一个工作目录，内含：
- `script.json`：`title`（标题）、`style`（风格）、`source`（原片来源）、`scenes`（每段一段 `narration` 配音稿）、`sfx_windows`（音效时间窗）、`timing`（时序表）。分镜稿的每段文字拼接后必须与该段配音稿逐字一致，否则构建脚本应直接报错停止。
- `assets/`：`Caveat-Bold.ttf`（手写体）、`hand-right-marker.png`（右手素材）、`sfx/marker_flip.mp3`（记号笔音效）。

### 制作步骤

1. **配音**：用所选 TTS 工具（选项见 §三）按段合成音频文件 `audio/scene_01.mp3`、`scene_02.mp3`……音色、语言按配置表，全片统一；每个音频文件须大于 1000 字节，否则视为合成失败。用 `ffprobe` 读取每个音频的实际时长，作为该段的时长依据。
2. **分镜**：按 `rules.md` 每段先排版式，每页换骨架；完整图形先画完，再写旁边的字；每个元素配一段真实配音片段，时长按词数占该段配音稿词数的比例分配，最短 1.2 秒（硬规则，不得缩短）；每段结束后画面定格 1.0 秒。
3. **渲染**：用 PIL 按 1920×1080 逐帧绘制，书写帧间隔 0.18 秒（约 5.5 帧/秒的手写速度），字幕按词数比例切分（单行 ≤42 字符），生成 `subs.srt` 与 `subs.ass`；每段用 FFmpeg 合成为一个片段（`format=yuv420p,fps=25`，libx264，veryfast），再用 concat 拼成整片 `merged.mp4`。策略分界处用白场淡入淡出 0.35 秒，其余为硬切。
4. **音效**：只在绘制图形或书写关键数字时响，音量低于配音（图形与数字 0.7，弹出与滑入 0.45）。混音一律用 numpy（`mix_sfx.py`），禁止用 ffmpeg amix 多路混音（24 路会卡住 30 分钟以上）。
5. **合成**：FFmpeg 烧录字幕、混入配音与音效，产出 `final.mp4`。整片渲染约 3–4 分钟。
6. **自查**：看每段最后一帧（不是中间帧），逐页检查重合、溢出、遮挡、乱码；改一处后全片复查同类问题；核对配音、字幕、画面逐句对应。
7. **发布包**：按 `core/templates/publish-package.md` 写标题、简介、标签；封面用 `core/scripts/make_cover.py` 按实际开头画面制作。
8. **上传**：`core/scripts/youtube_upload.py upload --manifest publish.json`，视频先传成 Private 并设 `publishAt`（UTC 时间，09:00 北京时间 = 01:00 UTC），到点由 YouTube 转公开。首次使用前须先完成一次 Google 授权（`youtube_upload.py auth`）：新建 Google Cloud 项目，启用 YouTube Data API v3，创建 OAuth 桌面应用并设为正式版（否则 token 7 天过期），完成一次授权后凭据存于 `~/.config/youtube-upload/`，不在仓库内。每人须为自己的账号各做一次，不可共用。上传使用 requests 可续传方式。TikTok 仅手机 App 手动发布。

### 各风格的制作路径（均已同步进仓库）

| 风格 | 入口 | 输入 |
|---|---|---|
| 白板手写 | `examples/landlord-method-v8/build_v8.py` | `script_v8.json`、配音、分镜 |
| PPT / 课程长片 | `core/scripts/build_ppt.py` + `core/scripts/pipeline.py` | `video.json`、PPT、按页配音 |

### 其他已验证的制作路线

- **PPT 路线**：`core/scripts/build_ppt.py`，输入 `video.json`，产出 `.pptx` 与逐页 PNG；再用 `core/scripts/pipeline.py`（PPT PNG + 按页配音 + SRT + FFmpeg 合成）产出横屏成片。`build_ppt.py` 需安装 `python-pptx`。
- **竖屏重剪路线**：`core/scripts/build_vertical_recut.py`，输入一个横屏项目目录，产出 1080×1920 竖屏成片，含 PIL 绘图、动效、字幕、FFmpeg 合成；加 `--no-tts` 可复用已有音频。
- **配音备选**：ElevenLabs（需 key，音质最好）；Edge TTS 需可访问 Bing 服务，否则选用本地 TTS。
